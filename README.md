# QuadTap 四格映射（Android V1.12）

QuadTap 是一个 Android 悬浮点击与选项位置识别原型。它把屏幕上的选项位置映射到固定的 A/B/C/D 四格悬浮面板上：
你按下面板上的某一格，它在当前页面找到对应选项的坐标并点击过去。

**它不会判断答案。** 本工具只做「按键 → 坐标」的映射，选什么完全由你决定。

## 定位优先级

1. **字母匹配** —— 扫描当前窗口和所有可交互窗口里的控件文本，识别 `A. 加速通过`、`B、停车让行`、`(C)`、`选项D` 等写法；
2. **位置兜底** —— 字母一个都匹配不上时启用。有些题库（例如驾考宝典 `com.handsgo.jiakao.android`）
   把 A/B/C/D 渲染成图片，文字节点里只有选项正文，任何要求字母的规则都不可能命中。
   这时按几何特征找出一列**等宽、等距、高度接近**的选项行，从上到下依次对应 A/B/C/D；
3. **手动校准记录** —— 使用你长按格子时记录的位置；
4. **截屏 + 中文 OCR** —— Android 11 及以上，且前三步都失败时，截图做本机文字识别。

这四条路径都要先通过**选项范围检查**：只有落在「已确证到的最高选项序号」以内的字母才会被点击，
题型无法确证时宁可不点（详见下方「功能」）。

## 功能

- **StandBy 式卡片切换**：四个功能区 **运行控制 / 识别与校准 / 运行日志 / 应用设置** 各占一页，
  可左右拖动切换（当前卡跟手位移并缩小淡出，新卡从反方向进入，220ms）；
  窄屏用顶部一行导航入口，宽屏（≥ 840dp）用左侧导航栏 ——
  点击导航与手势切换共用同一个页面状态，滑动只是补充手段，不是唯一入口；
- **按窗口宽度自适应**：断点是 `< 600dp` 窄屏 / `600–839dp` 中等 / `≥ 840dp` 宽屏，
  只看**当前可用窗口宽度**，不看设备型号；分屏按缩小后的窗口宽度判定。
  中等与宽屏下内容列限制最大宽度（720 / 1040dp）并居中，避免正文被拉成超长行；
- **配色跟随深浅主题**：四张卡片白天是高饱和品牌色（`#1677FF` / `#D8E9FF` / `#19C7C2` / `#2867F0`），
  夜间整体压暗、保留色相（`#10427F` / `#152A45` / `#0B3B38` / `#1B2B63`），其中
  「识别与校准」「运行日志」两张卡夜间会从浅底深字翻成深底浅字；深色主题页面背景为纯黑 `#000000`；
- **开关状态在卡片上清晰可辨**：轨道与滑块配色是显式指定的，不依赖主题 accent ——
  否则「开启」的蓝色与蓝色卡面几乎同色，开启后看不出状态；
- **运行控制卡**：显示真实运行状态、累计辅助答题次数、本次运行时长，并提供服务开关；
- **应用内启停**：关闭开关会立即停止辅助操作 —— 拒绝新的点击、取消排队任务、
  摘除悬浮窗、停止计时；再次开启时优先复用仍然连接的无障碍服务。
  停止只作用于 QuadTap 自己的辅助行为：Android 不允许应用自行**开启**无障碍服务，
  所以开关无法完全对称 —— 系统无障碍可能仍显示已连接，但 QuadTap 不再做任何事；
- **累计辅助答题次数**：只在 `dispatchGesture` 真正派发成功后 +1，保存在 SharedPreferences；
- **本次运行时长**：`HH:MM:SS`（小时可超过 24）。起点保存在服务里，
  切后台、熄屏或 Activity 重建都不会重置；停止后归零；
- **点击前先确证选项范围**：`allowedLabelCount` 表示「已确证到的最高选项序号」，
  **不是题目总项数**。序号超出的标签（例如判断题上的 C、D）会在**所有点击分支之前**被拒绝，
  节点直接命中也无法绕过；只识别到 A、B 时只允许 A、B，**不会**把它当成「这是判断题」；
  题型无法确证时不做节点/校准点击，转交 OCR 重新识别，OCR 也确证不了就仍然不点；
- A/B/C/D 四格悬浮面板，使用 `TYPE_ACCESSIBILITY_OVERLAY`，**不需要「显示在其他应用上层」权限**；
- **长按格子手动校准**：面板暂时隐藏，你直接点屏幕上该选项的真实位置即可记录。
  取点层是透明的，**不会真的点到目标应用**，因此不会误作答，也不依赖目标应用是否发送无障碍点击事件；
- 校准坐标按屏幕宽高的**相对比例**保存，旋转屏幕或换机后仍然可用；
- **限定显示的应用**：可以选定若干应用，面板只在这些应用位于前台时出现。
  切到别的应用时面板会被**真正移除**（`removeView`，不是设成透明），
  所以既不遮挡，也不会在它覆盖的位置吞掉触摸事件；
- **面板可拖动**，松手后自动吸附到屏幕左右边缘，位置会被记住；
- **方块大小可调**（34–76 dp），另有「恢复默认位置与大小」一键复位；
- 点击格子在屏幕上短暂画出本次识别到的选项范围，方便确认映射是否正确；
- **输入法弹出时自动隐藏面板**，避免打字时挡住候选栏；
- **主题可切换**：跟随系统 / 白天 / 黑夜，深色模式下状态栏图标自动反转；
- 适配 Android 15 的强制边到边：系统栏高度作为内边距让出，标题不会被状态栏压住；
- **黑色终端式日志窗口**：每次点击悬浮格都会把当次扫描的完整无障碍节点树、候选评分、逐条判定过程
  和 OCR 结果写进应用内的环形缓冲（最多 800 行，只存在内存里）。日志窗口高度固定
  （窄屏 268dp / 中等 300dp / 宽屏 360dp，且不超过可用高度的一半），**在窗口内部独立滚动**，
  日志再多也不会把页面撑长；接近底部时自动跟随最新日志，向上翻阅历史时保持阅读位置；
- 自动与手动识别之间有并发护栏，避免连点叠出多路截屏；
- **应用内更新**：直接检查 GitHub Releases、下载安装包并交给系统安装器，
  不用再手动去发布页下载。可在设置里关闭启动时自动检查。

## 识别不准时怎么办

「运行日志」页的终端窗口里有「复制」按钮，把内容发出来即可定位问题。日志里包含：

- 所有窗口的类型、层级、包名，以及哪些因为属于本应用而被跳过；
- 遍历到的每一个带文本的节点：文本原文、屏幕坐标、是否可点击、深度；
- 每个标签（A/B/C/D）的候选列表和各自评分，以及最终选中了哪一个；
- OCR 回退是否触发、截屏是否成功、识别出的每一行文字及其坐标和匹配结果；
- 最终点击坐标，以及它的来源（节点定位 / 已校准位置 / OCR）。

## 版本与验证状态

当前最新发布是 **V1.12**（`versionCode 13`）。

- **已验证**：用 Android SDK 35 + build-tools 35.0.0 + Gradle 8.9 **离线编译通过**
  （`assembleDebug` → `BUILD SUCCESSFUL`）；发布流程在 GitHub 上构建、`apksigner` 校验签名、
  生成 `SHA256SUMS.txt` 并发布 Release，全部通过；
- **未验证**：所有界面改动 —— 卡片切换的手势阈值、三档断点的实际观感、夜间配色、
  平板与分屏布局 —— **只做过静态审查与对比度计算，没有在真机或模拟器上运行过**
  （开发机没有连接设备，也没有安装模拟器镜像）。自动答题、OCR 与题型门禁同样只做过代码审查；
- 因此请把它当作**可用但未经真机验证**的版本：先在自己有权操作、且后果可承担的应用里试。

## 已知限制

- **识别逻辑的验证范围有限**：此前只在驾考宝典（`com.handsgo.jiakao.android`）上实测过。
  定位逻辑是按常见题库界面结构写的，换成别的应用很可能需要重新调整
  （界面改动本身尚未实测，见上方「版本与验证状态」）；
- 位置兜底靠的是几何特征（同列、等宽、等距）。如果目标应用把选项排成两列网格、
  或各选项宽度不一致，兜底就会失效，此时只能长按手动校准；
- OCR 回退依赖 Android 11+ 的截屏 API，系统版本更低时只有自动节点定位和手动校准两条路；
- OCR 对题型措辞、字体、背景对比度敏感，识别不到时会提示你改用长按校准；
- 判断题（正确/错误）只在没有 A–D 字母时按「正确→A、错误→B」处理；
- 四个标签的纵坐标顺序矛盾时**只记录日志、不再丢弃结果**（V1.2 起），
  所以极端情况下可能点到错误的选项；
- **界面尚未真机验证**：卡片切换的手势阈值（水平位移需大于垂直位移的 1.5 倍）、
  三档断点的具体取值、夜间配色与平板布局，都只做过静态审查和对比度计算，没有目视确认过；
- 日志区域为了支持文字选中，起点落在日志上的手势不会被识别为翻页 ——
  想换页请用顶部 / 侧边导航，或在卡片其他区域滑动；
- 平板宽屏下四张卡片内部的排版仍是单列（只做了外壳级自适应：侧边导航 + 内容最大宽度 + 日志加高）；
- 判断题与「只识别到 2 个选项的 4 选项题」在点击前检查中无法区分（都会判定为最高序号 2），
  因此判断题上点 C/D 会被拒绝，但 4 选项题若只扫到 A、B 两个也会被拒绝 ——
  这是有意的保守策略：宁可点不动，也不点错；
- Android 系统版本、目标应用界面结构、无障碍策略和厂商定制都会影响效果。

请先在你有权操作的应用中进行安全测试，并在确认映射准确后再使用。

## 技术方向

- Java / Android SDK（minSdk 26，compileSdk 35）
- Android AccessibilityService（`canRetrieveWindowContent` / `canPerformGestures` / `canTakeScreenshot`）
- Android 屏幕截图 API（API 30+），HARDWARE 位图转 ARGB_8888 软件位图
- Google ML Kit 中文文字识别
- **界面全部用原生 View 以代码构建**，没有 XML 布局、没有 Compose、没有第三方 UI 框架；
  卡片切换是自写的 `CardPager`（`ViewGroup` + `dispatchGesture` 级别的触摸拦截 + `ViewPropertyAnimator`）
- 自适应布局只用 `Configuration.screenWidthDp` 与 `LinearLayout` / `FrameLayout` / `ScrollView`，
  没有引入 ConstraintLayout
- 应用内更新用 `HttpURLConnection` + `FileProvider` + 系统安装器，不依赖任何更新 SDK

## 下载

已发布的版本见 [Releases](https://github.com/yuyibei2023/QuadTap/releases)。
每个版本附带 APK 和 `SHA256SUMS.txt` 校验文件，
文件名是 `QuadTap-v<版本>-release.apk`（已配正式签名）或 `QuadTap-v<版本>-debug.apk`（未配签名时回退）。

关于正式签名是什么、怎么配，见 [`docs/SIGNING.md`](docs/SIGNING.md)。

打标签即可自动发布：

```
git tag v1.12
git push origin v1.12
```

`.github/workflows/release.yml` 会自动构建 APK、生成校验文件，
并从下面这份变更记录里取出对应版本的段落作为发布说明。不需要配置任何个人令牌。
